# album_show · 我的唱片店

> 给每个人一间专属的「唱片店」，把你的听歌品味当成一件件藏品，陈列给朋友看。

## 为什么做这个（初衷）

音乐品味是一个人身份的一部分，但在流媒体时代，它被压缩成了一个「歌单列表」——没有空间感，没有温度，也不能逛。

我想还原的是**真实唱片店**的那种体验：

- 每个人拥有一间自己的店：门口有水泥墙、灯管招牌（店名可以自己 DIY），推开玻璃门走进去；
- 店内有两种陈列：**墙上**挂的是最想展示的精选唱片，**箱子里**插的是日常收藏；
- 它是社交的：搜索朋友的 ID，就能走进 TA 的店，看看 TA 在听什么、TA 给哪张专辑写了故事。

一句话：**把「我的 Spotify 歌单」变成「我的唱片店」。**

## 功能一览

- 注册 / 登录（用户名即店铺 ID，也是别人搜索你的入口）
- **外立面**：水泥墙 + 灯管 + 可自定义店名 + 玻璃门 + 人行道
- **店内**：分类标签（全部 / 爵士 / 嘻哈 / 流行 / 摇滚）
  - 墙上 · 我的精选（木质货架陈列）
  - 箱子里 · 我的收藏（周转箱插唱片）
- **专辑导入**：从 iTunes Search API 搜索，一键导入（封面自动抓高清图）
- **专辑故事**：点开任何一张唱片，可以写一段「我与这张专辑的故事」
- **逛店**：顶栏搜索别人的 ID，直接进 TA 的店

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React 18 + Vite + react-router | 轻量 SPA |
| 后端 | Express 4 | 单文件入口 |
| 数据库 | `node:sqlite`（DatabaseSync） | 单文件 DB，零原生编译依赖 |
| 认证 | `crypto.scryptSync` + Bearer token | 零第三方依赖 |
| 音乐数据 | iTunes Search API | 免费、无需 token、合法合规 |

> 刻意避开了网易云 / QQ 音乐的非官方接口（有法律风险），音乐元数据统一走 iTunes。

## 快速开始

```bash
# 1. 安装依赖（根 + server + client）
npm run install-all

# 2. 同时启动前后端
npm run dev
# 前端 http://localhost:5173
# 后端 http://localhost:4000
```

演示账号：`demo` / `demo123`（预置 8 张经典专辑）

## 已知不足（诚实清单）

当前版本在「氛围还原」上离目标差距很大，主要问题：

1. **外立面太「卡通」，没有真实水泥质感**
   现在的水泥墙是 CSS 渐变 + SVG 噪点模拟出来的，看起来像 2D 插画。我想要的是**真实水泥墙面的纹理**——颗粒、污渍、斑驳、光影起伏，目前完全没有还原。

2. **店内不是 3D 空间，专辑没有「物体感」**
   目前专辑是平铺的 DOM 卡片，只有很浅的 CSS 伪 3D。理想形态是一个**真正的 3D 空间**：唱片像实物一样有厚度、有体积，「摆」在墙上，可以走近看、环视整间店。

3. **箱子是「网页箱子」，不是真实箱子**
   参考图里是真实的唱片收纳箱（硬质周转箱，唱片斜插在里面、露出一半封面）。目前用 CSS 边框画的箱子非常假，一眼就是网页元素而不是实物。

4. **整体 UI 精致度不足**
   字体层级、间距节奏、光影层次、微动效都欠打磨，整体观感偏「草稿」，离能拿出门的成品有距离。

## 改进计划

- [ ] **真实材质贴图**：用实拍水泥墙照片 / 高分辨率无缝纹理替换 CSS 模拟（支持用户上传实拍图自定义装修）
- [ ] **3D 店内空间**：引入 Three.js / react-three-fiber，唱片成为有厚度的 3D 物体，相机可走动
- [ ] **真实箱子建模**：按参考图对周转箱做 3D 建模，唱片插入姿态有实物感
- [ ] **音乐试听**：接入 iTunes 30 秒 preview 片段，点击唱片可出声
- [ ] **社交增强**：关注好友、店铺留言板、根据收藏做品味推荐
- [ ] **装修风格预设**：不止水泥风，提供更多可切换的店铺风格
- [ ] **部署上线**：前后端部署到公网，支持移动端访问
